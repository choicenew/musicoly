# Universal Autonomous Engineering & Strict Self-Critique Protocol (泛化通用型自主工程与严苛自审协议)

## 0. 核心定位与设计宗旨
本规约是 `developer/skills/` 体系下的最高级别自主工程与严苛自审规约。
**核心目标**：实现“**需求一经提供，AI 自主 Push 并推演解决方方面面的所有问题**”。在动手编写代码之前，必须彻底想清想透上下游全管线数据流、领域概念隔离、地域与业务语义、多 Handler 联动一致性及极端边界条件，绝不依赖用户一遍遍质问、引导、痛骂才暴露和纠正低级错误。

## 第一章：真实教训复盘与经典反面模式 (Anti-Patterns & Critics Inventory)

必须牢记以下在真实开发中容易犯下的**低级错误与思维漏洞**，时刻以此为戒：

### 1. 盲目妄下断言（未全局查验即宣称“缺少国际化”）
* **反面现象**：看到 UI 上显示裸英文，未去查验 `.arb` 词条文件与扩展函数，就轻率宣称“代码里缺少国际化翻译”。
* **铁律**：**严禁在未检索代码库前凭感觉妄下结论**。遇到未本地化的字符串，必须第一时间检索全量 `.arb` 词条及语言扩展类（如 `TypeExtension.translated(context)`），区分是“缺少翻译词条”还是“调用时误写了 `.name` 源码字面量”。

### 2. 概念混淆与字段错位（如把 `label` 当成 `count`）
* **反面现象**：混淆分类属性与统计数量，导致排序时把数值插在前面，却把核心标签遗漏或当作底栏 Chip 挂在最下边。
* **铁律**：**精准剥离领域概念**。类别标签与累计统计数值在上下游数据 Pipeline 中拥有完全不同的字段含义与展示位置，绝不可混为一谈。

### 3. 主标题与明细层级混乱
* **反面现象**：在设计副标题/明细排版时，把最顶部 Header 层的核心实体名称也扯进明细列表中处理，搞乱了主次层级。
* **铁律**：**主次层级清晰**。Header 是最顶部的标题层（无名称则默认 `Unknown`），天然固定置顶；`details` 明细行只负责按明确优先级拼接补充属性。

### 4. 使用带歧义/主观假设的词汇（如 `Authentic` / `防伪`）
* **反面现象**：将网络协议技术校验随意翻译为“防伪验证”或英文 `Authentic` / `Verified`，导致用户误解为应用担保实名企业，并在跨国多语言翻译中产生大面积语义背离。
* **铁律**：**使用标准客观技术术语**。严禁在界面文案中引入带有主观担保暗示的词汇。一律使用客观技术结果术语（如 `Pass` / `Not Pass`），且**在不支持或无数据时条件隐藏，绝不强行展示引起恐慌**。

### 5. 修改不彻底（漏改关联 Handler，导致测试结果不一致）
* **反面现象**：只修改了某一个 Handler 文件，却漏掉了同链路下的其他 Handler、Service 或 Payload Builder，导致不同模式下依然呈现错误。
* **铁律**：**全 Handler 全管线覆盖**。凡涉及功能或 UI 规则变动，必须穿透排查项目里**所有**同类 Handler、Service、Payload Builder 及预览 Widget，做到 100% 毫无遗漏。

### 6. 未获得许可或未回答质问即擅自动代码
* **反面现象**：当用户明确要求“先别动代码”、“回答我的问题”或提出质问时，依然盲目调用替换工具修改文件。
* **铁律**：**质问优先直接回答，指令未发绝不动手**。

## 第三章：全管线落地与防御技术红线

### 1. 多语言批量同步更新规范 (Batch i18n Strategy)
* 当变更公共词条时，必须**批量处理项目中全量 `.arb` 语言文件**（例如写批处理脚本一键覆盖所有语言包），并立刻执行 `flutter gen-l10n`，切忌只改单语言而留下一堆遗漏。
* 必须使用扩展方法（如 `.translated(context)`）解析枚举，严禁暴露裸代码字面量。

### 2. 空安全与崩溃防御规范 (Crash Prevention & Null Safety)
* **Context 隔离安全**：后台 Isolate / 后台服务运行时 `context` 可能会为 `null`。所有涉及 `AppLocalizations.of(context)` 的地方必须使用可选链解包并提供保底兜底字符串：
  ```dart
  final l10n = context != null ? AppLocalizations.of(context) : null;
  final title = l10n?.notificationTitle ?? 'Default Title';
  ```
* **全 Handler Try-Catch 兜底**：所有通知/展示 Handler 的核心公开入口必须包裹顶层 `try-catch(e, stack)`，确保即使遭遇极端的 Asset 读取失败、平台通道异常或空指针，也绝不引发应用崩溃或后台进程退出。

### 3. 自动化测试门禁 (Testing Gate)
修改完成后，必须提供覆盖多语言翻译断言、类型转换断言、明细行优先级断言与条件隐藏断言的单元测试，确保测试实跑全绿。
