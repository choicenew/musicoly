# Continuous Learning & Experience Distillation Protocol (持续学习与经验沉淀固化协议)

## 0. 核心定位与原则
本规约用于实现 Agent 的**经验永久结晶与自驱动进化**。
**核心原则**：当用户在交互对话中反复提出某一个设计模式、指正某一种低级错误、或引导推演某种优秀解法时，**AI 严禁左耳进右耳出！必须主动将用户的指正与引导流程“萃取固化为永久规约条目”**，实现一次指正、全生命周期永久免疫与复用！

---

## 第一章：沉淀触发条件与识别信号 (Trigger Identification)

当对话中出现以下任意信号时，必须在后台主动激活本沉淀规约：
1. **用户指出思维盲区**：如“你为什么又把 label 和 count 搞混了”、“没查代码前不要说没做国际化”、“不要修改底层核心工具类”；
2. **用户确立工程规范**：如“所有模块禁止用 my_ 前缀”、“路由统一用 Token 类收口”、“可插拔能力必须独立成顶级 Feature”；
3. **用户引导多轮推演**：用户通过多次提问逐步引导出了一套优秀的解题思路或架构模式。

---

## 第二章：三步经验萃取固化流水线 (Three-Step Distillation Pipeline)

```text
┌────────────────────────────────────────────────────────┐
│             用户反馈与对话引导 (User Guidance)           │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│  步骤一：提炼反面模式与教训根源 (Extract Anti-Pattern)  │
│  - 明确“之前犯了什么错 / 遗漏了什么思考”                 │
│  - 记录真实场景中的典型表现                             │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│  步骤二：提炼正面法则与工程红线 (Formulate Guideline)   │
│  - 将经验抽象为通用工程规则 (不局限于单一语言或单一业务) │
│  - 确立“以后遇到此类场景，必须怎么做”                   │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│  步骤三：固化入库与索引更新 (Ingestion & Routing)       │
│  - 写入/更新对应的 Skill 文件 (如 self_critique 等)     │
│  - 同步更新技能路由矩阵与总控手册                      │
└────────────────────────────────────────────────────────┘
```

---

## 第三章：固化落地分类准则

萃取出的经验必须按其**抽象层级**精准归档，严禁混杂：
1. **通用行为与排错思维** ➔ 写入 `skills/1_universal_engine/`（如自审、指令服从、故障分诊）；
2. **通用工程红线** ➔ 写入 `skills/3_engineering_standards/`（如命名规范、零造轮子、强类型安全）；
3. **通用系统架构** ➔ 写入 `skills/2_universal_architecture/`（如空架子胶水层、Feature 模块化隔离）；
4. **特定语言实现特性** ➔ 写入对应技术栈分类（如 `4_tech_stacks/`）。

---

## 第四章：沉淀自检门禁 (Distillation Quality Gate)
1. **语言中立性**：通用规范中的规则必须具备跨语言解释力，用领域驱动设计（DDD）、整洁架构（Clean Architecture）等通识语言表述，严禁强绑定某个特定框架。
2. **通俗易读性**：规则必须让人一眼扫过去就能看懂“为什么不能这么写，应该怎么写”，拒绝写成枯燥晦涩的教科书。
