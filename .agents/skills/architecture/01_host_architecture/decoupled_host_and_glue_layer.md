# Decoupled Host Shell & Facade Glue Layer Architecture (纯空架子宿主与门面胶水层装配架构)

## 0. 适用场景
当项目为**重插件化、多数据源动态拓展、微包集群装配、异构媒体流聚合渲染**（如聚合论文、漫画、小说、音视频、壁纸等多模态应用）时选用的主 App 核心架构。

---

## 第一章：宿主 App 纯空架子定位 (App Shell Philosophy)

### 1. 宿主只是调度容器 (The Empty Shell Container)
* **核心职责**：主 App (`host_app`) 仅负责应用入口 (`main.dart`)、全局路由总表注册、顶层 Provider 挂载、外观主题配置与基础原生平台通道 (Bridge) 桥接。
* **绝对禁止实现具体业务**：宿主内部禁止编写任何特定媒体类型的卡片组件、二级详情页、阅读器或播放器。

### 2. 主 App 零 Map 转换红线 (Zero Host Map Transformation)
* **严禁手写 Map 提取**：主 App 内部**绝对禁止**手写任何 Map 字段提取、字典拼接、`raw['id']` 强转或数据降级逻辑。
* **违规报警机制**：主 App 中一旦出现手写 Map 转换，即表明架构产生越权腐烂！必须强制使用全工程约定的强类型实体（如 `MediaEntity`）贯通整条数据链路（插件清洗 ➔ 提升实体 ➔ UI 无损渲染）。

---

## 第二章：门面胶水层中枢规范 (Host Glue Layer - Wedding Chapel)

胶水层位于主 App 内部的 `lib/core/`（如 `core/algorithms/`、`core/hubs/`、`core/connectors/`），是宿主装配各个微包的**唯一中枢**：

```text
┌────────────────────────────────────────────────────────┐
│                   主 App (Host Shell Container)         │
│  ┌──────────────────────────────────────────────────┐  │
│  │   门面胶水层 (lib/core/ - The Wedding Chapel)       │  │
│  │   负责同时依赖并装配各个微包，向上提供统一 Facade 指令   │  │
│  └───────┬──────────────────────────┬───────────────┘  │
└──────────┼──────────────────────────┼──────────────────┘
           │ (单向依赖)                 │ (单向依赖)
           ▼                          ▼
┌──────────────────────────┐   ┌──────────────────────────┐
│ 功能微包 A (pyro_render)  │   │ 功能微包 B (pyro_edge_ai) │
│ (独立纯净, 终生不相往来)    │   │ (独立纯净, 终生不相往来)    │
└──────────────────────────┘   └──────────────────────────┘
```

### 1. 全工程唯一的“婚礼现场”
* 只有在宿主内部的门面胶水层，多个相互独立的微包才允许被同时引用，用于拼装具体的业务逻辑流水线。
* **防腐与指令翻译**：胶水层负责将各微包抛出的底层数据翻译成 UI 易懂的简单状态或展示指令。
* **隔离哨兵**：若某个微包需要被剔除、升级或替换，只需修改胶水层的装配逻辑，不准动宿主 UI 页面和其他微包。

### 2. Dashboard 拼装逻辑下沉
* **UI 表现层**：只准提供“通用坑位”（货架容器、网格插槽、氛围背景）。
* **业务组装下沉**：具体谁排第一排、展示哪些卡片、包含什么操作按钮，必须下沉到胶水层或具体的业务包中通过 Hub 动态注入宿主。
