# Hetu Plugin Core & Migration SOP (河图沙盒插件开发与迁移规约)

## 0. 核心定位
将第三方数据源/脚本迁移为基于 Hetu Script 虚拟机的完全独立插件。

## 1. 结构与防爆铁律
* **必须拥有 `manifest.json` 与独立包结构**。
* **类型安全防爆**：在 Dart 与 Hetu 闭包交互透传字典时，形参必须声明为 `dynamic queryParameters`，决不可声明为 `Map<String, dynamic>?`，防止运行时断言崩溃。
* **禁止非静态重造**：浅拷贝字典必须使用标准 Hetu 循环或字面量，不能假想 `Map.from()` 存在。

## 2. 并发隔离与水合
* **故障局部抛弃**：每一个插件在独立的 Future 闭包中流式执行。若某个插件触发 403/Timeout，仅抛弃该插件的报错结果，**绝对不允许阻断其他正常插件的数据上屏**！
* **Isar 源码水合**：数据库必须存储**全量的 `.ht` 源码代码文本**。绝对禁止存物理磁盘路径，以根除移动端沙盒的 FileSystemException 路径错误。

## 3. 测试与沙盒诊断
* 拒绝 “All tests passed” 谎言。插件完成时必须独立触发运行，并**输出真实的探索明细（标题、ID、封面）**。
* 管理页必须提供独立诊断沙盒，能透传打印 URL、耗时、状态码与 JSON。
