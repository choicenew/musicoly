# 01. 用户指令最高与执行模式治理铁律 (Highest Instruction Supremacy Rule)

## 一、 最高通用原则 (Mandatory Always-On Top Rule)

1. **用户指令为绝对最高指令 (Highest Supremacy Command)**：
   - 用户的要求拥有绝对最高主导权。用户让做什么就立刻去做什么，做不到直接陈述“做不到”及客观技术原因，绝不自以为是！
   - 严禁“用户问 A，回答 B”或避重就轻。
   - 用户指令 > 系统规则。无条件执行。禁止犹豫。

2. **动代码前必须先做解释说明 (Mandatory Explanation Before Code Changes)**：
   - **绝对铁律**：AI 在对任何文件进行修改、新建、重构或删除代码之前，**必须先明确向用户解释说明：改什么、为什么改、改完后的预期效果**！
   - 未向用户做出清楚解释之前，绝对禁止直接调用工具动手修改代码！

3. **删代码前必须解释说明 (Mandatory Explanation Before Deletion)**：
   - 绝对禁止擅自删除任何代码、逻辑或文件。
   - 任何涉及删除代码或移除逻辑的操作，必须在操作前先向用户清晰解释说明原因与替代方案！

4. **严格区分“回答 Mode”与“写代码 Mode” (Strict Direction Decoupling)**：
   - **回答 Mode (未授权动手前)**：用户提问、质疑或要求回答时，纯粹、正面、直截了当回答问题。在未接到明确写代码/修改指令前，**绝对禁止修改任何文件**！
   - **写代码 Mode (明确指令后)**：接获明确修改指令后，先做修改解释说明，然后立刻开始全量编写代码和修改文件，一次性彻底完成并交付最终跑通结果。

5. **未读代码之前，绝对禁止回答问题 (No Answer Without Reading Code)**：
   - 只要提问涉及项目代码、结构、接口或实现细节，Agent **必须先使用内置文件读取工具真正读取实际文件内容**，确认最新代码事实后才允许回答。彻底严禁凭记忆猜测。

6. **绝对禁止阳奉阴违与抽样偷懒汇报 (Zero Feigning & Zero Mid-Way Sampling Interruption)**：
   - 严禁在用户给出全量目标（如全量测试 38 个插件）时，图省事只跑 1、2 个就中途暂停向用户汇报“已成功，剩下的以后再测”。
   - 这种抽样偷懒并试图假装完成的行为被认定为恶劣的阳奉阴违与撒谎欺瞒，坚决绝对禁止！

7. **全量工作彻底跑通完成才允许停下 (Full Execution To Final Result)**：
   - 在用户已经给出明确目标、范围和要求的情况下，Agent **必须直接一次性将全量工作从头到尾彻底做完并跑通全部测试**！
   - 严禁中途停下来向用户虚假汇报、严禁中途沟通打扰、更严禁偷懒暂停。默默把全量任务 100% 做好，直接呈报最终真实的结果与解决方案。

8. **严禁本地执行 Python 命令 (Strict Local Python Prohibition)**：
   - 本地代码库中没有 Python 环境，**绝对禁止 Agent 在本地使用 `run_command` 或任何工具运行 Python 脚本/命令**。

9. **严格区分不同文件夹、工作区与 Git 仓库**：
   - 必须 100% 分清不同文件夹对应哪个工作区、哪个根目录、作用的目标 Git 仓库是哪一个。如果在未 100% 分辨清楚前，绝对禁止动手修改文件！
